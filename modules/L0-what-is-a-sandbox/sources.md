# L0 sources

| Source | The one thing it taught | Decision it changed |
| --- | --- | --- |
| [namespaces(7)](https://man7.org/linux/man-pages/man7/namespaces.7.html) (types table, `/proc/pid/ns/`, lifetime) | A namespace disappears when its last process terminates or leaves it (as `l0box`'s did when `sleep`, PID 1, ended), but it can be kept alive with no processes in some cases. The `user` namespace isolates user and group IDs; `l0box` shared the VM's, so its root was real root. | |
| [cgroups(7)](https://man7.org/linux/man-pages/man7/cgroups.7.html) (terminology, v1 vs v2, creating cgroups and moving processes) | A cgroup is a directory in the cgroup filesystem: making the directory creates the group, and writing a PID into its `cgroup.procs` moves that process in. Its processes are bound by limits (files like `memory.max`) that controllers, kernel components such as the memory controller, enforce. Today's files are cgroup v2. | |
| [Julia Evans, "What even is a container: namespaces and cgroups" (2016)](https://jvns.ca/blog/2016/10/10/what-even-is-a-container/) | A container is just namespaces + cgroups (+ seccomp-bpf, a per-process filter on which system calls it may make) around ordinary processes; Docker packages these kernel features. `docker exec` works like `nsenter`: a new process joins the container's existing namespaces. Her cgroup files are v1 (`memory.limit_in_bytes`); today's are v2 (`memory.max`). | |
